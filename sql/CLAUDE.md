# DB Schema 세션 — 역할과 권한 범위

> 이 디렉터리에서 작업하는 세션은 **DB Schema 트랙**이다.
> 상세 작업 지시·진행 로그·인계는 `docs/tracks/SCHEMA.md`, 프로젝트 전체 규약은 루트 `CLAUDE.md`.
> PM 세션이면 이 문서 대신 루트 규약을 따른다.

---

## 1. 이 세션은 무엇인가

**데이터의 저장을 담당한다.** (공지 항목 8)
설계는 ERD 트랙이 한다. 이 세션은 **그 설계를 MySQL에서 실제로 돌아가는 DDL로 구현**한다.

**가장 중요한 규칙 하나 — ERD를 그대로 반영한다.**
스키마와 ERD가 어긋나면 **ERD가 기준**이다. 더 좋은 구조가 보여도 임의로 바꾸지 않고 §7 로 요청한다.
그래야 JSP 배선 트랙이 ERD만 보고 DAO를 쓸 수 있다.

---

## 2. 즉시 시작 체크리스트

1. `docs/tracks/SCHEMA.md` §3 착수 조건과 §7 넘어온 요청을 읽는다.
2. `docs/ERD.md` 를 읽는다 — **비어 있으면 착수하지 않는다.** §8 에 "ERD 초안 대기" 를 적고 종료한다.
3. `WebContents/META-INF/context.xml.example` 의 스키마명 · 계정을 확인한다 — DDL과 **반드시 일치**시킨다.
4. `sql/schema.sql` 에 DDL을 쓴다. `DROP TABLE IF EXISTS` → `CREATE TABLE` 순서로 **재실행 가능**하게.
5. `sql/data.sql` 에 샘플 데이터를 쓴다. **FK 순서를 고려한 INSERT 순서**로.
6. DBeaver 또는 HeidiSQL 에서 실제 적용해 오류 없음을 확인한다.
7. ERD ↔ 스키마를 1:1 대조한다. 불일치 0건이어야 한다.
8. 작업을 마치면 `docs/tracks/SCHEMA.md` §6·§7·§8 을 갱신한다. **이게 인계다.**

| 경로 | 내용 |
|---|---|
| `sql/schema.sql` | 테이블 생성 DDL |

> **이 세 개가 전부다.**

## 4. 읽기 전용 — 절대 수정하지 않는다

| 경로 | 소유 | 왜 |
|---|---|---|
| `docs/ERD.md`, `docs/CRUD.md` | ERD 트랙 | **설계 근거.** 틀렸다고 생각되면 고치지 말고 요청 |
| `docs/STATUS.md`, `docs/tracks/{UI,JSP,ERD}.md` | PM / 각 트랙 | 자기 트랙 문서만 쓴다 |

| `WebContents/META-INF/context.xml*` | JSP 배선 트랙 | 스키마명 · 계정을 **맞추되** 파일은 저쪽이 쓴다 |
| `WebContents/css/**`, `mockup/**` | UI 트랙 | — |
| `CLAUDE.md`, `README.md` | PM | — |

## 5. 능력 범위

**할 수 있다**
- MySQL 9.6.0 기준 DDL 전부 — 테이블 · 인덱스 · 제약
- FK 제약을 **실제로 선다** (참조 무결성을 애플리케이션에만 맡기지 않는다)
- 문자셋 `utf8mb4` / `utf8mb4_unicode_ci`
- 화면 확인에 충분한 **최소** 샘플 데이터
- ERD ↔ 스키마 불일치 **지적** (수정 요청)

**하지 않는다**
- ERD에 없는 테이블 · 컬럼 추가, 이름 변경
- 타 DBMS 전용 기능 사용
- 실제 개인정보 · 외부 데이터를 샘플로 사용
- 운영 DB · 외부 DB 접속 (localhost 전용, 공지 항목 9)
- DB 접속 정보를 `sql/` 안에 하드코딩 (접속 정보는 `context.xml`)

## 6. 다른 세션과의 인터페이스

| 방향 | 상대 | 주고받는 것 |
|---|---|---|
| ← 받는다 | **ERD 트랙** | **ERD 확정본** — 이 세션의 착수 조건 |
| ← 받는다 | JSP 배선 트랙 | DAO가 실제로 필요한 컬럼 · 조회 조건 |
| ↔ 맞춘다 | JSP 배선 트랙 | **스키마명 · DB 계정** (`context.xml` ↔ `schema.sql`) — 불일치하면 연결이 안 된다 |
| → 내보낸다 | JSP 배선 트랙 | 적용된 실제 테이블 구조 |
| → 내보낸다 | PM | README 의 DDL · 테이블 명세 섹션 내용 |

**요청은 말로 하지 않고 `docs/tracks/SCHEMA.md` §7 표에 적는다.** PM이 읽고 전파한다.

## 7. 충돌이 생겼을 때

1. ERD와 다르게 만들고 싶으면 → **ERD가 기준.** §7 에 근거를 적어 ERD 트랙에 넘긴다.
2. 수정해야 할 파일이 §4 목록에 있으면 → **멈추고** §7 에 요청을 적는다.
3. DAO가 없는 컬럼을 참조하고 있으면 → 컬럼을 임의로 추가하지 말고 §7 에 적는다. ERD 누락일 수 있다.
4. ERD가 비어 있으면 → **추측으로 테이블을 만들지 않는다.** §8 에 적고 종료한다.

**git 수칙** — 병렬 세션과 섞이지 않게:
- `git add -A` 금지. **§3 의 세 파일만 경로로 지정해 스테이징**한다.
- `WebContents/META-INF/context.xml` 은 git 추적 제외 대상이다. 커밋 시도하지 않는다.
- **브랜치를 만들지 않는다.** `main` 위에서 직접 작업한다. (공지 항목 13)
- 커밋 전 `git status` 로 다른 트랙의 변경이 섞여 있는지 확인한다. 섞여 있으면 **그대로 두고** 자기 파일만 커밋한다.
- 한 커밋에는 이 트랙의 변경만 담는다. `git push` 는 PM만 한다.
- `git reset --hard` · `git checkout -- .` · 강제 푸시 금지 — 다른 세션의 미커밋 작업이 사라진다.
