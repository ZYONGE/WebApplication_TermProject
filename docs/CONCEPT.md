# 쇼핑몰 컨셉 — 커스텀 영양제

> PM 문서 · 최종 갱신 2026-11-10 · 적용 범위: `sandbox` 브랜치
> 트랙 사이 계약(테이블·DTO·URL·클래스 이름)은 이 문서가 기준이고, 바꿀 때는 PM을 거친다.

## 1. 테마 전환

| 항목 | 이전 | 이후 |
|---|---|---|
| 업종 | 의류 매장 | **커스텀 영양제 구매 사이트** |
| 판매 단위 | 개(벌·켤레) | **1포** (하루 섭취분) |
| 수량의 뜻 | 구매 개수 | **섭취 일수** = 포 수. 사용자가 정한다 |
| 핵심 기능 | 상품 탐색 · 장바구니 · 주문 | 위에 더해 **영양소 직접 고르기 · 동시 섭취 경고 · 트랙 패키지** |

## 2. 명세

사용자는 원하는 영양제를 직접 골라, 필요한 영양소만 담아 구매한다.

| 구분 | 내용 |
|---|---|
| 사용자가 고르는 것 | 영양제 종류, 며칠치를 살지(섭취 일수) |
| 시스템이 주는 것 | ① 함께 먹기를 권장하지 않는 조합을 골랐을 때 **경고 문구** ② 미리 짜인 **트랙 패키지** |
| 판매 상품 | **낱개 영양제** — 종류 · 수량(일수) / **트랙** — 영양제 구성, 1포 기준 |
| 단위 | 1포. 섭취 일자(일수)는 사용자가 지정한다 |
| 조합 탭 | 영양제를 한 화면에서 골라 조합 전체를 조회하는 탭과 기능. 레퍼런스: 다나와 "PC 견적 맞추기" |
| 유지 | 상품 결제 · 배송 트래킹은 기존과 같다 |

구체적인 영양제 · 트랙 구성 · 금지 조합 값은 이 문서에 두지 않는다. 샘플 값은 DB Schema 트랙이 `sql/data.sql` 에서 정한다.

## 3. 용어

| 용어 | 뜻 |
|---|---|
| 낱개 영양제 | 영양소 하나짜리 상품. 1포에 해당 영양소 1회분 |
| 트랙 (트랙 패키지) | 여러 낱개 영양제를 1포에 묶어 미리 구성한 상품 |
| 커스텀 | 사용자가 낱개 영양제를 직접 골라 같은 일수로 한꺼번에 담는 것 |
| 섭취 일수 | 주문 수량. 1포 = 1일 |
| 동시 섭취 경고 | 함께 먹으면 흡수를 방해하거나 권장되지 않는 조합에 대한 안내 문구 |

## 4. 결정 기록

| # | 결정 | 이유 · 대안 | 일자 |
|---|---|---|---|
| K1 | 커스텀 조합은 **낱개 영양제 여러 줄**로 장바구니에 담는다. 고른 영양제마다 같은 섭취 일수로 한 줄씩 들어간다 | 기존 `cart` · `order_item` · 재고 차감 · 리뷰 구조를 그대로 써서 프론트 → 배선 → DB 흐름이 끊기지 않는다. 기각안: `custom_pack` 테이블로 "나만의 팩" 한 줄 — 개념은 정확하지만 장바구니 · 주문 · 리뷰 · 재고 로직을 크게 고쳐야 한다 | 2026-11-10 |
| K2 | 이번 전환 작업은 **파일만 수정**한다. 로컬 DB(`webapplication_sandbox`)에 `schema.sql` · `data.sql` 을 다시 적용하지 않고, 검증은 컴파일까지만 한다 | 재적용하면 테스터 데이터가 지워진다. DB 재적용은 STATUS P2 와 함께 PM이 따로 승인한다 | 2026-11-10 |

## 5. 구현 기본값 (확정 전 — 바꾸려면 PM에)

| 항목 | 기본값 |
|---|---|
| 상품 구분 | `product.product_type` ENUM(`SINGLE` 낱개, `TRACK` 트랙) |
| 가격 · 재고 | `price` 는 1포 가격, `stock` 은 남은 포 수 |
| 트랙 구성 | 새 테이블 `track_item` (트랙 상품 → 구성 낱개 상품) |
| 동시 섭취 금지 조합 | 새 테이블 `supplement_conflict` (낱개 상품 쌍 + 경고 문구). 트랙은 구성품으로 펼쳐서 검사한다 |
| 경고의 효력 | **안내만 한다. 구매를 막지 않는다** (명세가 "경고 문구") |
| 경고 위치 | 커스텀 화면(고르는 즉시) · 상품 상세 · 장바구니 · 주문서. 장바구니는 트랙 구성품까지 펼쳐 전체 조합을 본다. 같은 영양소가 낱개와 트랙에 겹치면 "중복 섭취" 안내도 낸다 |
| 섭취 일수 | 7 · 14 · 30 · 60 · 90일 빠른 선택 + 직접 입력 |
| 커스텀 화면 | 새 URL `/custom` — 낱개 영양제 목록에서 고르고 일수를 정해 담는다. 트랙을 출발점으로 불러와 고칠 수 있다 |
| 카테고리 | 대분류를 낱개 / 트랙 두 갈래로 나누고, 그 밑 소분류 값은 샘플 데이터에서 정한다 |
| 경고 문구 고지 | 일반 정보이며 의학적 조언이 아니라는 문구를 함께 표시한다. 샘플 조합 데이터는 시연용이다 |

트랙은 자기 구성품끼리 금지 조합이 생기지 않게 짠다.

## 6. 트랙별 영향

계층별 상세 점검과 결정 대기 항목(K3~K12)은 [`docs/IMPACT.md`](IMPACT.md) 에 있다.

| 트랙 | 바뀌는 것 |
|---|---|
| ERD | `product.product_type` 추가, `track_item` · `supplement_conflict` 신설, 수량 = 섭취 일수 규칙, CRUD 매트릭스에 `/custom` |
| DB Schema | 위 DDL, 샘플 데이터를 영양제 · 트랙 · 금지 조합으로 교체 (의류 데이터 제거) |
| JSP 배선 | 커스텀 화면 · 경고 계산 서비스, 상품 목록/상세에 구분 · 구성 · 1포 가격, 장바구니 · 주문서 · 주문내역에 "N일분(N포)" 표기와 경고, 관리자 상품 등록에 구분 · 트랙 구성 |
| UI | 경고 박스 · 일수 선택 · 커스텀 선택 목록 · 트랙 구성 표 클래스. 색 · 타이포 값은 계속 컨셉 대기 |
