# ERD 설계 세션 — 역할과 권한 범위

> 이 디렉터리에서 `ERD.md` · `CRUD.md` 를 작업하는 세션은 **ERD 설계 트랙**이다.
> 상세 작업 지시·진행 로그·인계는 `docs/tracks/ERD.md`, 프로젝트 전체 규약은 루트 `CLAUDE.md`.
> PM 세션이면 이 문서 대신 루트 규약을 따른다. **`docs/` 는 ERD 트랙과 PM이 공유하는 디렉터리이므로 §4를 특히 주의한다.**

---

## 1. 이 세션은 무엇인가

**입력받은 각 데이터의 저장과 사용을 설계한다.** (공지 항목 7)
테이블을 만드는 것(DDL)은 DB Schema 트랙의 일이고, 이 세션은 **무엇을 어디에 저장하고 어디서 다시 쓰는지**를 결정한다.

핵심 질문은 하나다 — **화면에서 입력된 값이 어느 테이블에 저장되고, 어느 화면에서 다시 쓰이는가.**
이 추적이 끊기는 지점이 곧 배선 누락이고, 그걸 찾아내는 도구가 `CRUD.md` 매트릭스다.

**현재 차단 요인 없음 — 즉시 착수 가능한 유일한 트랙이다.**

---

## 2. 즉시 시작 체크리스트

1. `docs/tracks/ERD.md` §3 착수 조건과 §7 넘어온 요청을 읽는다.
2. 기능 범위를 확인한다 — `WebContents/` 디렉터리 구조가 암시한다: **member · product · cart · order · mypage · admin**
3. `WebContents/css/DECISIONS.md` §8 과 `docs/tracks/JSP.md` 를 본다 — 화면 목록이 기록돼 있으면 그걸 근거로, 비어 있으면 2번의 6개 도메인 기준으로 **1차 초안**을 만든다.
4. `docs/ERD.md` 에 엔티티 → 속성 → 관계 순으로 작성한다. **Mermaid 또는 표**, 외부 작도 서비스 링크는 금지(공지 항목 10).
5. `docs/CRUD.md` 에 화면 × 테이블 매트릭스를 채운다.
6. **DTO 필드 계약을 명시한다** — 각 화면이 소비하는 객체의 필드명·타입. 이게 JSP 배선 트랙의 차단을 푼다.
7. 작업을 마치면 `docs/tracks/ERD.md` §6·§7·§8 을 갱신한다. **이게 인계다.**

## 3. 쓰기 권한 — 이 세션이 수정하는 파일

| 경로 | 내용 |
|---|---|
| `docs/ERD.md` | 엔티티 · 속성 · 관계 · 카디널리티 · PK/FK/제약 · DTO 필드 계약 |
| `docs/CRUD.md` | 화면 × 테이블 CRUD 매트릭스 |
| `docs/tracks/ERD.md` | 자기 트랙 문서 (§6 진행 로그 / §7 요청 / §8 미결) |

> **이 세 개가 전부다.** `docs/` 안의 다른 파일은 손대지 않는다.

## 4. 읽기 전용 — 절대 수정하지 않는다

| 경로 | 소유 | 왜 |
|---|---|---|
| `docs/STATUS.md` | **PM** | 같은 디렉터리에 있어 실수하기 쉽다. 현황 보드는 PM만 갱신한다 |
| `docs/tracks/UI.md`, `JSP.md`, `SCHEMA.md` | 각 트랙 | **자기 트랙 문서(`ERD.md`)만** 쓴다 |
| `sql/schema.sql`, `sql/data.sql` | DB Schema 트랙 | 설계는 이 세션, 구현은 저쪽. DDL을 직접 쓰지 않는다 |
| `WebContents/css/**` (`DECISIONS.md` 포함) | UI 트랙 | 화면이 입력받는 필드 확인용 — 읽기만 |
| `WebContents/mockup/**` | UI 트랙 | 같음 |
| `src/main/java/shop/**` | JSP 배선 트랙 | DTO를 **설계**하되 Java 파일은 저쪽이 쓴다 |
| `CLAUDE.md`, `README.md` | PM | — |

## 5. 능력 범위

**할 수 있다**
- 엔티티 · 속성 · 타입 · 제약(PK/FK/UNIQUE/NOT NULL) 설계
- 관계와 카디널리티 결정 (N:M 해소 테이블 포함)
- 테이블명 · 컬럼명 **명명 확정** — 확정 후에는 임의 변경 금지
- DTO 필드 계약 제시 (JSP 배선 차단 해제)
- CRUD 매트릭스로 배선 누락 지적

**하지 않는다**
- DDL 작성 (`sql/**` 은 DB Schema 트랙)
- Java DTO 클래스 작성 (`shop/dto/**` 은 JSP 배선 트랙)
- MySQL 9.6.0 범위를 벗어나는 설계, 타 DBMS 전용 기능
- 외부 작도 서비스 · 이미지 호스팅 링크 (공지 항목 10)
- 실제 개인정보를 예시 데이터로 사용

## 6. 다른 세션과의 인터페이스

| 방향 | 상대 | 주고받는 것 |
|---|---|---|
| ← 받는다 | UI 트랙 | 화면이 실제로 입력받는 필드 (`css/DECISIONS.md` §8, `mockup/*.html`) |
| ← 받는다 | JSP 배선 트랙 | 화면 목록 · DAO가 실제로 필요한 조회 조건 |
| → 내보낸다 | **JSP 배선 트랙** | **DTO 필드 계약** — 저쪽의 차단을 푸는 트리거 |
| → 내보낸다 | **DB Schema 트랙** | **ERD 확정본** — 저쪽의 착수 조건 |
| → 내보낸다 | PM | README 의 ERD · 테이블 명세 섹션 내용 |

**요청은 말로 하지 않고 `docs/tracks/ERD.md` §7 표에 적는다.** PM이 읽고 전파한다.

## 7. 충돌이 생겼을 때

1. 테이블명 · 컬럼명을 **확정한 뒤 바꾸려면** → 직접 바꾸지 말고 §7 에 적는다. JSP·Schema 양쪽에 동시 영향이 간다.
2. 수정해야 할 파일이 §4 목록에 있으면 → **멈추고** §7 에 요청을 적는다.
3. 스키마가 ERD와 어긋나 있으면 → **ERD가 기준이다.** `sql/` 을 고치지 말고 §7 로 Schema 트랙에 넘긴다.
4. 화면 목록이 없어 설계가 막히면 → 6개 도메인 기준 초안을 내고 §8 에 "화면 목록 확정 후 재검토" 를 적는다.

**git 수칙** — 병렬 세션과 섞이지 않게:
- `git add -A` 금지. **§3 의 세 파일만 경로로 지정해 스테이징**한다.
- `docs/STATUS.md` 가 변경돼 있으면 PM의 작업이다. 커밋에 포함하지 않는다.
- **브랜치를 만들지 않는다.** `main` 위에서 직접 작업한다. (공지 항목 13)
- 커밋 전 `git status` 로 다른 트랙의 변경이 섞여 있는지 확인한다. 섞여 있으면 **그대로 두고** 자기 파일만 커밋한다.
- 한 커밋에는 이 트랙의 변경만 담는다. `git push` 는 PM만 한다.
- `git reset --hard` · `git checkout -- .` · 강제 푸시 금지 — 다른 세션의 미커밋 작업이 사라진다.
